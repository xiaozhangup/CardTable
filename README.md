独立的 Paper / Octopus 26.3 牌桌插件，依赖 CrabKotlin 2.3.20。内置三人经典斗地主、癞子斗地主和 2–10 人 UNO；牌桌、菜单、实体显示、皮肤、音符盒音乐、座椅和资金托管共用，游戏状态与规则留在各自的 `GameSession` 中。

## 安装

1. 安装 `CrabKotlin-2.3.20-paper.jar` 和 `CardTable-1.3.49.jar`，使用 JDK 25。
2. 使用 CraftEngine 时，将 `CardTable-CraftEngine-1.3.49.zip` 中的唯一 `cardtable` 目录放入 `plugins/CraftEngine/resources/`，执行 `ce reload all` 并重新接收资源包。升级时删除 CE resources 下旧的 `doudizhu`、`uno` 目录，避免重复注册。共 257 个物品，包含两套扑克和两套 UNO 原创像素牌、牌背、按钮，以及 Blockbench 制作的完整桌椅模型；菜单使用原版物品，CE 卡牌直接引用世界模型，不再打包独立 GUI 贴图。斗地主中文语音使用 `palemoky/fight-the-landlord` 的男女声录音，UNO 复用音符盒音乐；语音来源与许可说明见 [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)。
3. CraftEngine、Vault 是可选依赖。未安装 CE 时使用原版物品、名称和文字显示；收费桌需要 Vault 与实际经济服务。坐姿由插件通过原版实体自行实现，无需 GSit 或 CMI。

桌面和无靠背方凳采用无碰撞的 display 实体，不会放置或破坏世界方块。普通三人、四人桌请预留至少 7×7 的平地，相邻中心至少间隔 6.4 格；更多人数的桌子会扩大，建桌时按双方座位半径检查间距。面向牌桌方向后创建，右键空位或 `/ct join` 自动定位并坐下。坐骑没有点击范围，已有人的座位不再保留入座热区。Shift 下座会按正常离桌规则退出当前对局；关闭菜单仍保留座位。

入座后直接在世界牌桌操作，不自动弹出菜单。自己的手牌和全息按钮仅自己可见；第一次右键手牌抬起选中，自己回合再次右键任意已选牌，打出整组选中的牌。左键切换选择，可取消抬起的牌；全息「出牌」按钮继续保留。准备、叫分、不要、提示，以及 UNO 摸牌、选色、宣告和挑战全部使用全息文字按钮。每块按钮的文字和底板均可点击，按实际朝向计算射线命中。

手牌与回合动作按钮交换原先区域。手牌始终单行，每页最多 20 张，在可用宽度内按本页张数调整重叠间距，选中后抬高；超过 20 张时使用两侧全息按钮翻页，跨页保留选牌。桌面轮次提示均无背景；UNO 在正中央显示白色出牌方向符号 `⟳` / `⟲`，反转后按实际规则方向更新；斗地主在顶部悬浮字第三行显示“出牌方向 逆时针”，灰色标签配白色方向文本，不使用方向符号。方向以桌面正上方视角为准。当前行动者用实心三角形 `▼` 指向该席位，不显示姓名；仅该席位前显示白色倒计时，三角形位于倒计时靠近玩家的一侧。倒计时与三角形整体相较 1.3.7 向桌心收回 0.10 格，其余座位前默认留空；被 UNO 禁手跳过的席位短暂显示白色 `∅`，倒计时不在其他位置重复。

成功出牌后，公开牌从出牌者席位依次飞向桌面牌堆，落地后正面朝上按先后顺序叠放，最新一张在最上层，所有人都能看到；斗地主在桌心周围约 2.1 格范围内分散叠放本局全部已出牌，各牌落点和角度固定；UNO 继续只渲染紧凑牌堆上层最多 16 张，其余牌保留在游戏数据中。UNO 洗回弃牌时桌面同步收回旧牌，斗地主保留本局出牌历史，并额外为每位玩家显示最新多张组合的朝向摘要。正常获胜后让最后出牌动画完成，并保留最终公开牌堆到下一局发牌；取消对局、对局中离桌或关闭牌桌会清空展示。斗地主的三张底牌横排居中，略微缩小以留在散牌内侧空区，UNO 摸牌堆的牌背仍显示在弃牌堆另一侧。「设置」和「离桌」放在两侧，与回合动作分开。菜单仅提供个人牌面、音乐、补齐机器人与只读参与者头颅，通过全息「设置」或 `/ct open` 主动打开；右键人偶不会弹菜单。

选牌、倒计时、手牌与按钮刷新会更新现有显示实体，移除本次不再显示的内容，避免整批删除再生成引起的刷新闪烁。方向各显示一处：斗地主位于顶部抬头，UNO 位于桌心。顶部采用每桌共用的公开抬头：前两行显示玩法与阶段、该阶段必要的数据，斗地主对局期间第三行另列出牌方向；使用原版默认字号和默认半透明背景，主题色标题、灰色标签、白色数值，UNO 当前颜色显示为“当前牌面: 颜色”，前缀为灰色，颜色名称使用对应的四色。文字分组使用空格，空位不显示入座文字。玩家与机器人的名字交给原版名牌显示，人物状态移到各席位面前的公开手牌上方，对本人隐藏，只向其他观察者展示。采用两行布局：对局中第一行显示身份及金色“机器人”标识，“玩家”标识为黄色；第二行显示“手牌 x 张”，数字为白色，其余文字为灰色；地主为淡金色，农民为浅绿色，UNO 宣告显示黄色“UNO!”。等待时真人只显示一行“准备就绪”或“未准备”，准备就绪的机器人第一行显示“准备就绪”，第二行显示金色“机器人”；未准备的机器人仍按“机器人 / 未准备”排列，不显示“等待开局”或空白行；按实际行数居中，隐藏手牌数，不重复姓名。状态文字使用独立的客户端虚拟 TextDisplay，按桌位坐标定位，不加入服务器世界实体列表，也不挂载到 Player 或 Mannequin 上。显示与隐藏跟随对应角色的实体追踪关系；CardTable 不创建或发送计分板队伍，不修改角色的乘客列表，原版姓名及其他插件的名牌继续按各自规则显示。状态文字使用 0.5 倍字号、客户端默认背景、无文字阴影及环境亮度，居中补偿 TextDisplay 的一个像素横向内边距；文字块中心位于席位向桌心 0.75 格、桌面原点上方 1.10 格，与公开牌背共用水平坐标，状态行间距为 0.125 格。按观察者眼睛位置分别计算文字朝向，文字固定在手牌上方；仅内容、位置偏移或朝向变化时更新 metadata，离座、离开追踪范围和停服时清理。

玩家个人牌面选择只保存在本次插件运行的内存中，重启后恢复牌桌默认牌面，不再读取或写入 `preferences.yml`。音乐开关继续仅在本次在线期间生效。聊天文本及 `{0}`、`{1}` 变量说明见 [MESSAGES.md](MESSAGES.md)，该文件用于文案审阅，不作为运行时配置加载。

## 使用

管理员创建免费桌并选玩法：

```text
/ct create casual doudizhu
/ct option casual laizi true
/ct bet casual 0
```

`laizi false` 为经典玩法，`true` 为癞子玩法。修改规则、底注或回合时间前需要全员离桌。

| 命令 | 作用 |
| --- | --- |
| `/ct` | 已入座时打开本桌设置，否则打开牌桌设置列表 |
| `/ct join <桌名>` | 在附近加入牌桌 |
| `/ct open [桌名]` | 打开牌桌设置，不提供对局操作 |
| `/ct bot [add/fill/remove/clear]` | 添加、补齐、移除机器人；默认补齐，限免费桌 |
| `/ct ready` | 准备或取消准备，满三人且全部准备后发牌 |
| `/ct bid <0..3>` | 不叫或叫分，只能提高当前叫分 |
| `/ct draw`、`/ct color <red/yellow/green/blue>` | UNO 摸牌、万能牌选择颜色 |
| `/ct uno`、`/ct catch` | UNO 宣告、抓漏叫 |
| `/ct accept`、`/ct challenge` | UNO 接受 +4 或挑战 |
| `/ct hint`、`/ct play`、`/ct pass` | 提示选牌、确认出牌、不要 |
| `/ct select <编号,编号>` | 切换对应手牌选中状态；日常可直接点牌 |
| `/ct skin <皮肤>` | 切换自己的牌面，默认 classic/jade |
| `/ct music` | 切换本次在线期间的音乐 |
| `/ct leave` | 离桌；出牌阶段所属阵营判负，叫分阶段取消并退款 |
| `/ct list`、`/ct games` | 列出牌桌及已注册游戏 |
| `/ct create <桌名> [游戏]` | 在当前位置建桌 |
| `/ct createat <桌名> <世界> <x> <y> <z> <游戏>` | 控制台建桌 |
| `/ct game <桌名> <游戏>` | 切换游戏，清除旧游戏选项 |
| `/ct option <桌名> <键> <值>` | 设置该游戏支持的规则选项 |
| `/ct bet <桌名> <底注>` | 每桌独立底注，0 免费 |
| `/ct time <桌名> <秒>` | 每桌 5..300 秒的操作时间 |
| `/ct setskin <桌名> <皮肤>` | 更换牌桌默认皮肤 |
| `/ct delete <桌名>` | 移除实体、座椅并退回未完局预扣 |
| `/ct reload` | 无人入座时重载插件配置与牌桌 |

别名 `/ddz`、`/cardtable`；游玩权限 `cardtable.play` 默认开放，建桌及配置权限 `cardtable.admin` 默认 OP。服务器命令白名单需要允许这些命令。

## 斗地主规则

54 张牌按 17/17/17 加三张底牌发牌，最高叫分玩家成为地主并拿底牌。全部不叫时重新发牌并轮换首叫者。支持单张、对子、三张、三带一、三带二、顺子、连对、飞机及单/对翅、四带二单、四带两对、炸弹和王炸。顺子、连对、飞机主体不含 2 和王；翅膀不与主体重复，对翅点数不同，单翅可带对子。

癞子随机选择 3..2 的一个普通点数，该点数的四张牌可变成 3..2，不能变成王。自动选择能压过上一手的最低合法解释；出牌名称注明原牌到实际点数。炸弹强度为软炸 < 硬炸 < 四癞子炸 < 王炸。炸弹、王炸、春天和反春天翻倍，默认最多 64 倍。超时叫分自动不叫，跟牌自动不要，首出自动最小单张。

离桌、断线、死亡或离桌超过 `max-distance` 会按离桌规则处理；关闭菜单不离桌。胜负后保留座位，真人取消准备，机器人保持准备，可开始下一局。

## UNO 规则

```text
/ct create uno_table uno
/ct option uno_table seats 4
```

`seats` 为 2..10，默认 4。至少两人入座且所有已入座玩家准备后开局，不必坐满。采用经典 108 张牌，每人 7 张，按颜色或数字/符号接牌；每次出一张，不叠加罚抽、不抢出、不使用 7-0 换手。四色分别标注 R/Y/G/B，变色和 +4 均须选择后续颜色。

跳过、反转、+2、变色、+4 与双人规则按 [Mattel 经典规则](https://service.mattel.com/instruction_sheets/UNO%20Basic%20IS.pdf)及[双人补充](https://service.mattel.com/instruction_sheets/42001pr.pdf)处理。+2 下家抽 2 张并跳过；+4 下家可接受抽 4 张，或挑战。+4 仅在出牌前没有原当前颜色的牌时合法；挑战成功则出牌者抽 4 张，挑战者继续出牌，失败则挑战者抽 6 张并跳过。挑战证据仅发给挑战者，不公开其他人的手牌。

可主动摸 1 张，即使手中已有可出牌；摸后只能出刚摸到的牌或“不要”，不能再出原有手牌。剩 1 张时要喊 UNO，也可在自己有 2 张时预先宣告；漏叫被别人抓到罚摸 2 张，捕获窗口到后续玩家开始出牌/摸牌为止，+2 自动罚摸也会关闭窗口。牌堆耗尽时保留弃牌堆顶牌，将其余弃牌洗回。

一局以清空手牌为胜，记录其余玩家手牌总分：数字为本值，行动牌 20，万能牌 50。本版采用单局模式；不会自动累计到 500 分。最后一张为罚抽牌时先完成罚抽/挑战再计分。赢家保留座位，大家重新准备即可再开局。游戏中离桌、断线或超距会取消整局并退款。

世界手牌始终单行，每页最多 20 张，按本页张数自适应重叠间距，超过 20 张使用左右全息按钮翻页，选牌跨页保留。菜单不显示手牌或出牌控件。别人只看到 UNO 牌背与数量。桌心使用固定 `minecraft:uniform` 字体的白色 `⟳` / `⟲` 表示实际轮转方向，提示无背景；当前席位前显示白色倒计时及指向该席位的实心三角形，三角形更靠近玩家。双人反转仍按规则跳过对手并由出牌者继续。个人 `classic`、`jade` 皮肤均支持 UNO。参见[UNO 素材说明](craftengine/cardtable/docs/uno.md)。

开局翻到禁手牌或对局中打出禁手牌时，被跳过的席位在平时指针所在的第二行只显示白色 `∅`，不显示数字。提示持续 30 tick，最后 6 tick 淡出；若很快再次轮到该席位，正常倒计时与三角形优先恢复。此提示只对应 SKIP 禁手牌，罚抽、反转和主动“不要”不触发；最后一张禁手牌立即获胜时也不发提示。

普通摸牌与各类罚抽按实际取得的非零张数播放动画：公开牌背从桌面底牌区的固定抽牌堆位置飞向摸牌席位，每张飞行 12 tick，多张相隔 2 tick 出发。包括开局 +2、+2/+4、挑战处罚和漏叫 UNO；开局每人发 7 张不播放此动画。规则、手牌和轮次立即生效，操作不等待动画结束。动画不公开摸到的牌面或编号；最后 +2/+4 的实际罚抽动画可在结算后继续完成。

## 机器人策略

机器人使用 Minecraft 原版 `Mannequin` 人偶显示，外部 Python 进程直接调用 [RLCard 原始规则代理](docs/AI_SOURCES.md)。插件把自己的牌、公共牌桌信息和合法动作传给代理，再由既有游戏规则引擎检查并执行返回动作。插件处理癞子合法动作、UNO 宣告及 +4 挑战；包装程序补充只看自己手牌的叫分策略。

每次插件启动在 Crab 异步任务中读取名称缓存，再从 [NameMC 名称页](https://namemc.com/minecraft-names) 拉取名称。名称、皮肤、来源玩家 UUID、纹理签名与来源说明统一保存在 `plugins/CardTable/namemc-cache.json`，名称位于 `names` 数组；抓取成功原子更新对应部分，HTTP 错误、超时或无有效名称时保留旧缓存。游戏线程只读取内存池，同桌大小写忽略去重，补齐机器人前一次性选足名字；没有 `namemc-cache.json` 时，会先释放 JAR 内置的默认缓存，包含 59 个名称和 8 套签名皮肤，随后仍按原流程异步刷新；首次抓取失败也可以使用默认缓存。昵称在入座时确定，刷新和换局不改名；原版名牌、聊天、菜单和对局播报使用同一昵称。

皮肤来源独立于可用昵称：启动时从 [NameMC 皮肤页](https://namemc.com/minecraft-skins) 选择最多 8 个来源玩家，通过 Mojang 官方服务获取他们当前穿着的完整签名纹理，保存到统一缓存的 `skins` 数组。这可能与 NameMC 的历史皮肤页面不同；原始纹理属性保留 slim 模型及披风信息，不再用固定 Steve/Alex 材质覆盖。启动先加载已有缓存，再异步刷新，失败继续使用缓存；尚无皮肤时暂用原版默认外观，缓存就绪后应用到已生成假人，已应用的皮肤不随刷新更换。

只读取当前格式的 `namemc-cache.json`，其中 `names`、`skins` 和 `source` 必须完整；不读取、迁移或删除旧格式缓存。名称与皮肤共用同一个缓存写入锁，分别刷新不会覆盖另一部分。

假人使用原版可见自定义名牌，隐藏默认 NPC 描述。每次成功出牌触发一次原版主手挥动，斗地主一次多张组合也只挥一次；不要、摸牌、叫分或界面刷新不触发。

默认启用机器人。首次启动会在 `plugins/CardTable/env/` 后台下载 Python 并安装 RLCard 依赖，无需预装 Python 或填写启动命令；后续启动复用环境并自动启动 AI。日志出现 `External AI is ready: rlcard-rule.` 后即可添加机器人。安装日志在 `env/setup.log`，运行日志在 `env/process.log`；关闭或重载插件时一并结束相关进程。详见 [AI 运行环境说明](docs/AI_RUNTIME.md)。

玩家右键空位坐下，再点击全息「补齐机器人」和「准备」即可开始。设置菜单也提供“补齐机器人”和“移除机器人”；人偶自动准备，真人可与其他真人、机器人混坐。游戏中不能移除机器人；最后真人离桌时清理所有人偶。机器人只能加入底注 0 的免费桌。命令 `/ct join <桌名>`、`/ct bot`、`/ct ready` 继续保留。

规则代理需要 Python、RLCard 和 NumPy，不需要训练权重或 PyTorch；自动环境、可选外部程序及协议见 [AI 运行环境说明](docs/AI_RUNTIME.md)。进程输入不包含对手私牌及抽牌堆顺序。开源来源、固定提交、规则差异见[调研说明](docs/AI_SOURCES.md)，版权与许可见 [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)。

## Vault 与资金

每份输赢 = 底注 × 叫分 × 倍数。地主赢获得两份，两位农民各付一份；农民赢则相反。开局每人预扣 `底注 × 3 × max-multiplier × 2`，确保作为地主也能覆盖最大损失；例如底注 1、封顶 64 时每人须有 384。结算退回预扣加净输赢。底注不能超出经济插件的小数精度。

UNO 每位开局只预扣本桌底注；每位输者付一份底注，赢家得到 `底注 × (参赛人数 − 1)`，退款或结算复用同一资金服务。

`economy.yml` 原子保存托管与待退款记录。正常停服和重启后的已确认未完局托管会退款；充值明确失败的记录保留并每 30 秒及玩家登录重试。

Vault 没有事务幂等键。进程若在外部扣款/充值调用中被强杀，结果可能不明；`withdrawing`/`depositing` 记录不会盲目重复，日志会标明记录号。停服后核对经济插件余额：withdrawing 已扣款改为 pending，未扣款删除；depositing 已付删除，未付改为 pending，再启动。不要删除尚未处理的资金文件。

## 皮肤与音乐

`config.yml` 的 `skin-prefixes` 可增加自己的 CE 资源前缀。标准扑克牌后缀为 `spade/heart/club/diamond_3..10/j/q/k/a/2`、`joker_small`、`joker_big`、`back`。新游戏可定义自己的 `CardFace.asset` 后缀。改配置后 `/ct reload`，改 CE 素材后 `ce reload all`；既有桌子会在 CE 完成重载后重新显示。

`music.yml` 包含原创建桌循环的音符事件，使用原版 harp/bass 音符盒音色，无需资源包；`.score` 与试听 WAV 位于素材目录。

斗地主使用 [palemoky/fight-the-landlord](https://github.com/palemoky/fight-the-landlord/tree/6a2b07bd71a21e0c564277a235846e7f3cf589b1) 的男女声录音，经 FFmpeg 转为单声道 Vorbis OGG，随统一 CE 资源包发布。`doudizhu-voice: female` 为默认女声，可改为 `male`；`voice: false` 可全局关闭。无人入座后执行 `/ct reload` 应用配置。声音事件为 `doudizhu:voice.{female|male}.{event}`，向本桌在线玩家播放，音源在桌心，分类为 VOICE。

单张、对子、三张播报实际点数，癞子按本次出牌解释后的点数播报；三带、顺子、连对、飞机、四带二及炸弹播报对应牌型。三种飞机共用“飞机”录音。正分叫牌统一播“叫地主”，0 分播“不叫”，具体分数由文字显示；主动不要使用“不要”或“过”的录音。上游没有准确的叫分、开局、春天或结算人声，因此不混入旧 eSpeak 合成音，结算时保留最后一手出牌声，不再向全桌说“你赢了”。

两套语音共 106 个事件、108 个音频文件。原 MP3、固定提交与校验值、转换工具及仓库 GPL-3.0 许可证一并保留；上游未注明音频作者与原始授权，仓库许可证不等于已核实录音权属。参见 [素材说明](craftengine/cardtable/docs/doudizhu.md)及 [第三方说明](THIRD_PARTY_NOTICES.md)。
